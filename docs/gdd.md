# 游戏设计总纲（GDD）

> 状态: 持续更新 | 最近更新: 2026-10-06

本文档是游戏设计的**唯一入口总纲**：先读这里，再按导航表跳转到各专题文件。
工程落地计划见 [roadmap.md](roadmap.md)，工程规范见 [rules.md](rules.md)。

## 一、一句话定位

一款**明亮画风的类银河恶魔城**：核心玩法为流畅的平台跳跃与战斗；
世界由多个风格迥异的区域组成，以「能力锁」驱动探索与回溯。
灵感来源：《奥日》的流动感与明亮基调、《空洞骑士》的世界结构与能力解锁逻辑。

## 二、核心体验支柱

这四条支柱是全游戏的最高设计准则。任何新方案（新能力、新敌人、新区域）都应至少服务于其中一条，且不得破坏其余支柱。

1. **流动感**：Ori 式平台跳跃——移动行云流水、关卡无缝衔接。玩家应能凭直觉连续完成一系列动作，操作本身即乐趣。
2. **战斗反馈**：战斗是移动的延伸，节奏明快、打击反馈充分。战斗不应打断探索的流动，而是它的一部分。
3. **世界发现感**：区域风格差异鲜明 + 能力解锁改变世界。核心循环为「探索 → 遇到能力门 → 获得能力 → 回溯通过」，追求"啊哈时刻"。
4. **明亮氛围**：视觉基调明亮（区别于空洞骑士式压抑），以光影与色彩营造氛围；世界呈现「有希望的奇境」，而非绝望的废墟。

## 五、维护规范

- **状态标记**：每份文档头部与导航表标注状态——「已确定」（拍板结论，改动需记录决策）、「草案」（推进中的设计）、「待定」（只有开放问题）。避免把草案当结论。
- **单一入口**：任何新方案先读本文件导航表定位专题；新增专题文件必须回到第四节登记。
- **决策留痕**：重要设计决定（含推翻旧决定）记入 [decisions.md](decisions.md)，可追溯「为什么这样做」。
- **主题单一**：专题文件只讲一个主题，内容超过约 200 行时拆分为新文件并在导航表登记。
- **交叉引用代替重复**：roadmap 已有内容（资产格式、里程碑细节）用链接引用，不在设计文档中复制。
